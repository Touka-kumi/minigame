# 周期算法BC小游戏

> 虚拟金币仅供算法演示，不可兑换、不涉及真实支付。

## 启动

需要 Node.js 20 或更高版本，项目没有第三方依赖。

```bash
node server.js
```

或：

```bash
npm start
```

Windows 也可以双击 `start.bat`。打开 <http://localhost:3000>。

默认监听 `0.0.0.0:3000`，启动时会打印局域网地址。默认账户为 `demo`，同一服务下多台设备打开即共享余额、期号和上期结果。

### 可选环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DATA_FILE` | `data/wallet.json` | 持久化文件 |

## 周期规则

- 每 **150 秒** 一期，按 Unix 毫秒时间对齐：`00:00`、`00:02:30`、`00:05:00`……
- **开奖前 5 秒停止接单**，前端倒计时切换为“等待开奖”。
- 每位用户每期最多 **20 笔**。
- 普通玩法每期只能锁定一个结果，例如先投“大”后本期只能继续投“大”，不能再投“小”“双”“大单”等。
- **猜数字例外**：本期可以更换不同位数和数字连续投注，但不能和其他玩法混投。
- 余额在下注时立即扣除；到期后统一结算，命中返还总额自动加回余额。
- 服务端每 500ms 检查一次到期期号；即使没有客户端在线，也会按时开奖并写入 JSON。
- 当前期号、上一期结果、余额和历史均持久化，重启后会接着运行。
- 如果服务停机跨越了多个周期，启动时会先结算停机前保留的那一期，再直接进入当前周期；停机期间没有客户端参与的空周期不做补开。

## 安全边界

5 秒封盘、单期 20 笔和同结果锁定可以显著提高脚本操控成本，但**不能彻底消除种子可计算问题**。当前结果由该期公开的下单数、最后一单毫秒和总投入决定；20 笔已经足以在没有随机补偿的情况下做有限次种子试探。取数方式为低 11 位无偏模型，倍率按真实组合概率定价。

## 玩法、真实概率与倍率

取数修正后，五个选中数字在 0–9 上近似均匀，总结果空间为 100,000 种五位数组合。

| 玩法 | 命中条件 | 真实概率 | 返还总额倍率 | 期望返还/投入 |
| --- | --- | ---: | ---: | ---: |
| 大 | 和值 24–45 | 44% | 2.2× | 0.968 |
| 小 | 和值 0–21 | 44% | 2.2× | 0.968 |
| 单 | 和值为单数，且不是和值 | 44% | 2.2× | 0.968 |
| 双 | 和值为双数，且不是和值 | 44% | 2.2× | 0.968 |
| 大单 | 大且为单 | 20.508% | 4.7× | 0.963876 |
| 小单 | 小且为单 | 23.492% | 4.1× | 0.963172 |
| 和值 | 和值 22–23 | 12% | 8.0× | 0.96 |
| 猜数字 | 指定位置数字完全猜中 | 10% | 9.7× | 0.97 |

**倍率说明：** 这里的倍率是命中后的 **返还总额倍数**，包含本金。整体保留约 3%–4% 的庄家优势。例如下注 100 金币、2.2×，命中返还 220 金币，净盈利 120 金币；猜数字 9.7× 命中返还 970 金币，净盈利 870 金币。

大单和小单的倍率不同，是因为在五位数字的精确组合分布中，两者的真实概率不同：

- 大单：20,508 / 100,000 = 20.508%
- 小单：23,492 / 100,000 = 23.492%

### 猜数字

前端点击“猜数字”后：

1. 选择第 1–5 位；
2. 选择 0–9 中的一个数字；
3. 确认下单。

开奖结果会展示五位数字。例如结果为 `3 7 1 0 5`，猜“第 3 位 = 1”即命中，返还总额 9.7 倍。

## 开奖算法

1. 取该期 **总注单数** `orderNo`。
2. 若 `orderNo < 20`，从 `[20 - orderNo, 100]` 中随机加入补偿量，得到 `effectiveQty`；空期为 `orderNo = 0`，补偿区间为 `[20, 100]`。
3. 取该期 **投入金币总数** `totalStake`。
4. 取该期 **最后一笔下单的毫秒时间**；若该期无人下注，使用期号开始时间。
5. 将 `effectiveQty`、毫秒时间、`totalStake` 依次拼接成种子数字。
6. 对种子数字做 SHA-256，得到 64 位十六进制哈希。
7. 去掉首尾各 2 位，取中间 60 位，拆成 5 段 × 12 位。
8. 每段是 48 位值。经十进制转换后取**低 11 位**（对 `10^11` 取模并补零到 11 位），得到近似均匀的 11 位数字串。
9. 取该 11 位数字串的末位作为 1-based 索引（0 视为第 10 位），从第 1–10 位中取出一个数字；末位不参与取数，避免索引 0 自取末位造成偏差。
10. 五个数字求和：
    - `0–21`：小
    - `22–23`：和值
    - `24–45`：大
    - 单双按和值奇偶判断。
11. 结果五位数字就是五段各取出的那个数字，用于猜数字玩法。

> 48 位值无法均匀覆盖完整的 15 位十进制范围。此前取左侧补零后的前 10 位，会让 0/1/2 被过度采样；现在改为取低位 11 位，并用末位索引第 1–10 位，使每一位数字接近均匀，倍率才与真实概率对应。


### 历史追溯

点击左上角“历史”按钮后，顶部会显示一张带图表图标的 **近100期单双大小走势图**：

- 每一期同时显示“大/小/和”与“单/双”两个非数字字符；
- 按从旧到新排列，最新一期在末尾高亮；
- 默认折叠显示最近一部分，点击“展开100期”后完整展示近 100 期每一期的结果；
- 展开后可点击“收起走势”恢复紧凑模式；
- 桌面端自动换行展示，移动端可上下滚动查看；
- 颜色区分大、小、和、单、双。

走势图下方显示最近 20 期已结算记录。每一期可以展开查看：

- 本期投入金币总数、注单数量、最后一单时间、结算时间；
- 进位数量、随机补偿；
- 时间相关数与种子数字；
- 完整 64 位 SHA-256 哈希，以及高亮的中间 60 位；
- 五段十进制、末位索引和实际取出的数字；
- 求和判定和最终结果；
- 当前账户在该期的投注明细和盈亏。

服务端最多保留最近 100 期完整开奖记录。

## 数据与同步

- 数据保存在 `data/wallet.json`，每次变更立即原子写入。
- 最近 100 期完整开奖记录（含哈希、时间、总投入、分段过程）持久化保存，并用于近100期走势图。
- 新账户初始余额 **10,000 金币**。
- 默认账户 `demo`；访问 `?uid=your_name` 可使用独立账户。
- 多台设备访问同一个 `uid` 时共享余额、期号和上期结果。
- 旧版 `schemaVersion: 1` 数据会保留余额并迁移到周期制；上一版本保存的 `lastRound` 会迁移进期次历史。
- 如数据文件损坏，会备份为 `wallet.json.corrupt-<时间戳>` 后重新初始化。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/api/state?uid=demo` | 余额、当前期、上期结果、配置 |
| `GET` | `/api/history?uid=demo&limit=20` | 最近期次、完整哈希与计算过程 |
| `POST` | `/api/recharge?uid=demo` | 模拟充值，body：`{"amount":1000}` |
| `POST` | `/api/bet?uid=demo` | 下注，body：`{"type":"大","amount":100}` |
| `POST` | `/api/bet?uid=demo` | 猜数字，body：`{"type":"猜数字","amount":100,"position":3,"digit":7}` |

所有开奖和结算由服务端完成，前端只负责选择、展示和倒计时。
